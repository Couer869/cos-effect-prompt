# Nano Banana 编辑提示词要点

> 背景知识，帮助写出更专业的提示词。核心结论都已在 SKILL.md 中体现，这里讲"为什么"。

## 它是什么

Nano Banana 是 Google Gemini 图像模型（Gemini 2.5 Flash Image 及后续版本）的社区昵称。它吃的是**自然语言**，不是 SD 的逗号 tag。它最大的两个能力：

1. **编辑**：上传一张照片，用一段话告诉它改哪里、加什么，它能语义识别并局部修改。
2. **一致性**：编辑时保持主体角色/场景风格统一，避免"画风突变"。

对 COS 后期特效来说，这就是理想的"AI 后期师"——你给它角色照，它给你加上魔法阵/火焰/光效，而不把人物画崩。

## 编辑模式的核心原则

### 1. 明确"加什么 + 保持什么"

编辑提示词必须交代两件事：**要改变的部分**和**绝对不变的部分**。官方建议"Be explicit about what to keep exactly the same"。保持项说得越具体（面部、妆容、发型、服饰、动作），越不容易把人物重绘。

### 2. 正向描述，不要"不要"

Nano Banana 没有负向提示词。与其说"不要糊"，不如说"保持五官锐利清晰"。与其说"不要让特效显得假"，不如说"特效自然融入照片的光影与透视"。

### 3. 强动词开头

提示词第一句用一个明确的动作动词，告诉模型主操作是什么——本技能统一用"在这张照片上添加……"。这比"我希望……"更有效。

### 4. 讲视觉效果，不讲抽象概念

描述特效要"看得见"：颜色、形状、运动、光与物的关系。说"火焰从她掌心腾起，火星四溅，橙红与金黄交织"远比说"加入火焰特效，要帅气"有效。

### 5. 控制光影，特效才"长"在照片里

一张图里只有一个主光源方向。所有添加的特效光都要服从这个光源，或者明确说明它带来了新的光源（如"魔法阵的光照亮角色面部"）。这样特效才有体积感，不会像贴图。

## 摄影与电影术语（用于提升质感）

这些词放进提示词能显著提升专业感，按需使用：

### 光线
- 逆光 backlight：从角色背后打光，勾勒轮廓
- 轮廓光 rim light：边缘亮线，与背景分离
- 体积光 volumetric light：可见光柱（丁达尔效应）
- 环境光 ambient light：场景整体光线
- 三点布光 three-point lighting：主光/辅光/轮廓光
- 高光比 high contrast：明暗对比强
- 暗调低光 chiaoscuro：明暗强烈对比的戏剧性布光
- 金色时刻 golden hour：日出日落暖光

### 镜头与构图
- 浅景深 shallow depth of field：主体清晰背景虚化
- 广角 wide-angle / 特写 close-up / 低角度 low angle / 俯视 top-down
- 大光圈 f/1.8：背景柔化
- 焦点 focus：对焦位置
- 画幅 aspect ratio：如 1:1 / 3:4 / 9:16 / 16:9

### 画质与风格
- 电影感调色 cinematic color grading
- 胶片颗粒 film grain
- 8K 分辨率 / 高解析 sharp details
- 写实 hyper-realistic / 二次元 anime style / 厚涂 digital painting

## 中文提示词写作建议

- 中文在 Nano Banana 上效果良好，但**画面描述用词要具体**，避免空泛形容词。
- 中文提示词可以混入少量摄影术语（逆光、体积光、景深），术语用中文即可。
- 一段话内信息密度要高，但保持自然语序，不要堆砌短语。

## JSON 指令说明

Nano Banana 本质是语言模型，**结构化的 JSON 指令同样有效**，且比一段自由文本更无歧义。本技能输出的 JSON 之所以有效：

- `base_rules` / `constraints` 把"什么不许动"写成显式规则，让编辑更保守、不破坏角色一致性；
- 每个处理模块（`body_sculpting` / `special_effects` 等）把"改哪里、改成什么样"与画面表现分开描述；
- `integration` 把"光影/噪点统一"作为全局要求，避免多模块叠加后画质割裂。

用户把 JSON 指令连同照片一起粘贴/上传即可。JSON 里的中文值就是给模型的画面描述，遵循本文件前面的"讲视觉效果、正向描述"原则。

## 透视一致性（所有提示词必含）

任何新增/修改的元素都必须符合照片原有的**透视关系**，否则会像贴图一样"浮"在画面上。这是 `base_rules` / `integration` / `constraints` 里透视兜底的原理。

| 术语 | 含义 | 提示词写法 |
|---|---|---|
| 灭点（vanishing point） | 平行线的汇聚点 | 贴地元素（法阵 / 投影 / 水洼）贴合地面灭点方向，线条向灭点收敛 |
| 相机角度（camera angle） | 俯视 / 仰视 / 平视 | 元素可见面随角度变化：俯视看到顶面，仰视看到底面 |
| 景深（depth of field） | 近大远小与虚实 | 前景元素更大更虚，远处更小更实 |
| 地面贴合 | 贴地物体随透视形变 | 近端宽、远端窄，高度随纵深递减 |

**判断标准**：新元素的形状、朝向、大小、投影，全部以照片的灭点、相机角度、景深为基准，不凭空设定。

## 官方公式参考（生成模式）

如果偶尔要从零生成（用户没有照片），用官方结构：

`[主体 Subject] + [动作 Action] + [场景 Location] + [构图 Composition] + [风格 Style]`

本技能主场景是编辑已有照片，生成模式仅作为兜底。
